# 冻结前向只读观察

当前冻结策略与原交易服务保持不变。新增 `python -m src.v131.observe` 仅以
SQLite `mode=ro` / `query_only` 读取两本账本及现有日志；不调用行情接口、交易函数或历史重述。
写入范围仅为本轮数据目录的 `forward_observation`，不覆盖已审阅报告或验收 ZIP。

已有旧影子账户的 daily_report 函数会写入旧账户，不能复用于这两本隔离账本。
因此这里只补充状态汇总，并在 `daily`、`weekly` 保存当前日/周截至检查时的摘要。
这不是完整收盘净值曲线。净收益已经包含账本费用；另列成本不再次从净收益扣除。
预留不是新增资产；持仓按账本最后已有价格估值，可能滞后。最大回撤只基于实际采样快照，
未采样时段为 UNKNOWN，不利用行情重算来填补。

`latest.json` 与 `RUNTIME_CHECK.md` 提供两本现金、预留、持仓、费用、净收益、交易数、
采样回撤和动量减对照差异。下一次决策使用 NYSE 日历，分别通过 America/New_York 与
Europe/Madrid 转换，覆盖欧美不同周切换夏令时的情况。

`decisions` 保存现有决策记录、信号、跳过原因、意图创建时间，以及已持久化输入的观察时哈希。
原 `received_at` 是输入整理完成时记录，不能当作旧行情的网络接收时间；后者缺失就写 UNKNOWN。
没有用文件修改时间、观察时间或运行报告生成时间反推接收时间。只读归档不能补救原调用未记录的
逐次 HTTP 接收时间、原始文件精确使用版本，或在两次观察之间被覆盖的中间重试。若这些证据未来
需要完整精度，属于另行明确授权的日志改造；本轮未更改或重启冻结交易进程。

已在当前 Codex 对话建立每小时只读巡检（automation `v1-3-1`），运行上述汇总入口；
状态不变时保持安静，发生运行异常、首次完整周期证据或需要用户操作时才通知。
它依赖本机与 Codex 可运行，不承诺休眠期间采样。与交易服务的 Windows 登录任务相互独立，
不会重复启动交易管理器。

`cycle_status.json` 跟踪自然周期证据。只有真实关联的买入/退出意图及事件、持仓快照、
待结算款和金额可核对的真实结算都存在时，才生成 `first_natural_cycle_<账本>.zip`。
原引擎只有汇总结算事件，没有逐笔结算 ID，因此证据说明其聚合口径。缺少中间证据时保持待验证，
不伪造记录，也不覆盖已导出的首个周期包。ZIP 只包含选定事件和哈希，不包含数据库、密钥或行情库。
