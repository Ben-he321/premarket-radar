# B1.2 回放存储与恢复口径

这次存储优化是为了解决 16 GB 本机处理连续 L1 报价时的内存峰值。它不改变信号、报价时间、订单、费用、仓位、止损或财报规则，也不按结果删除报价。原始行情文件仍完整保留在本地缓存中。

`initial_v1` 保留优化前记录。MRVL 的完整真实回放为 590924 个事件、1 次买入成交、2 次卖出成交，2026-01-08 完成结算，现金 5376.96 USD。优化前 checkpoint 为 252033838 字节；这些事实是工程等价核对基线，不是组合收益或策略有效性证明。

## 保存与归档

`src.ben_b1_2.compact.CompactReplayEngine` 继承 B1.2 时窗扩展及 B1.1 原交易内核。每个完整输入批次后将已处理事件的准确 ID、内容摘要和已过时且没有被消费的盘口库存保存到该账户目录的 `replay_archive.sqlite`。当前盘口、所有发生过消费的库存、持仓、订单、财务状态和指标历史继续保留在 checkpoint。

同一时间戳的 Q1 报价组没有结束时，不归档、不提前排序、不提前创建意图。一个交易日可以有多个完整归档批次，例如收盘后 1 分钟数据批次和盘后入场批次。所有真实输入事件仍按原顺序执行，没有日内报价降采样。

checkpoint 和 CSV 使用流式写入，避免同时复制整份状态。各独立样本结束后释放其内存中的行情表；磁盘数据及既有样本结果保持原样。

## 恢复与重复输入

- checkpoint 只认领已经写入其财务状态的归档代际。
- SQLite 已提交、checkpoint 尚未替换时发生中断，旧 checkpoint 不会把这部分事件误认为已经入账。恢复后需重新执行，并与已提交但尚未认领的批次摘要一致，才可认领该代际。
- 已归档的相同事件 ID 必须通过内容摘要核对，即使调用方把其时间改成未来，也不能绕过冲突检查。
- 当前盘口与被消费的库存不被清除；旧过时报价或换 ID 的旧报价不能重新获得可成交数量。
- 归档缺失、摘要损坏、代际不一致均明确失败，不回退到空账户。
- Compact checkpoint 有独立版本标记，普通未归档引擎不能误读该状态。

## 输入摘要与证据包

新的输入摘要是“归档批次哈希链 + 当前尚未归档事件摘要”。它明确区别于旧版对全内存事件表计算的单一哈希，不能声称两个格式的哈希应该相等。金融等价检查比较实际现金、成交时间、数量、价格、费用、订单、结算和权益，不忽略经济字段的差异。

`ARCHIVE_MANIFEST.json` 保留每个批次的事件数、库存数、摘要、前序哈希与截止时间。CSV 的 `quote_inventory.csv` 范围是当前盘口和发生过消费的库存；零消费旧库存仍在本地私有归档和完整原始行情中，不能把精简 CSV 说成全部原始盘口。

`replay_archive.sqlite` 及 WAL 文件用于本地恢复，**不进入 verification ZIP**。验证包只包含摘要、来源、金融结果和恢复测试证据。复制 checkpoint 独立恢复时还需要对应的私有归档和原始输入；只拿验证 ZIP 不能还原完整行情库。

## 实际核对入口

优化前源码摘要和 MRVL 结果保存在本轮 `samples/initial_v1/PRESERVED_FOR_RESOURCE_OPT.json`。`engineering/MRVL_INPUT_PRESERVATION_BEFORE_COMPACT.json` 核对了 116 个输入对象，全部一致，未调用行情接口。

优化后的真实对等任务采用 `PinnedHoldingQuoteProvider`，只读原 MRVL 的 `HOLDING_QUOTE_REQUESTS.json` 及 `INPUT_HASHES.json`，未实例化行情客户端、未重新下载行情。`engineering/MRVL_REAL_ECONOMIC_EQUIVALENCE.json` 已实际通过：590924 个事件，以及 fills、orders、campaigns、account_events、daily_equity 五张金融表全字段一致，仅规范化独立运行名称；恢复检查通过，旧文件保持原样。这项通过只证明存储优化没有改变该既定真实路径的经济结果。

## 样本收尾的验收边界

当前冻结的独立样本适配器先写 `sample_run_complete`，随后生成 `RECOVERY_IDEMPOTENCY.json`。如果恰好在两次写入之间崩溃，仅凭 `sample_run_complete` 不能声称恢复核对已经完成；入口复用也不会自动补做该检查。交付时必须逐一核对全部 40 个样本的恢复文件及 `same_state=true`，比较表将缺失或失败单独列为未验证。此已知收尾边界不以重跑旧结果掩盖。

完成自然买卖结算、恢复检查通过，以及逐点输入完整，是三件不同的事。比较表同时保留原摘要的 `coverage_status` 和 `data_unknown_decision_count`；不能把闭合的财务周期直接表述为所有输入和观察记录均已通过资格检查。
